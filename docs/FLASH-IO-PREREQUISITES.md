# Flash I/O prerequisites

The combined predictive-prefetch/coalescing engine build passed **all 43 native tests** using owned generated fixtures. All four tested architecture gates exercised adjacent pairs with both one and two I/O lanes. Qwen3MoE and split-model gates also exercised real predictive jobs, scoring, consumption and exact useful/unused speculative-byte conservation. [Build, source, all 38 binary hashes and native evidence](../benchmarks/results/flash-prefetch-coalescing-native.json).

The source chain verified 5,253 original tracked blobs plus four baseline additions (5,257 files), then the 5,260-file composition. The guarded build took 657.58 seconds and native tests 197.32 seconds. Both reaped all children and recorded no hard resource events or new swap activity. These are build/native prerequisites, not model performance results. The rebuilt CLI subsequently passed the fresh original 353-token/SHA code oracle with both features OFF and diagnostics ON. It reported 3.914 tok/s; speculative, predictive and coalesced traffic counters stayed zero, with successful demand accounting, no failed reads and complete cleanup. This single-arm correctness/observability check establishes no old/new speedup. [Exact model parity](../benchmarks/results/flash-prefetch-coalescing-off-parity.json). The [separate feature screens](lab-notes/FLASH-IO-SCREENS.md) are now terminal: coalescing completed below its whole-request advance gate, while predictive prefetch stopped at the byte-waste ceiling. Neither setting advances to a standalone full task or promotion.

## io_uring is available; engine integration remains unqualified

The separate V3 probe completed **48 exact synthetic reads**, 24 each at queue depths 1 and 8, with synchronous direct-I/O controls, short reads, EOF and zero outstanding/prepared operations at cleanup. Both ring setups returned 0. Requests used flags 0; liburing 2.15 automatically returned `IORING_SETUP_NO_SQARRAY` (65536). This is documented library behavior at the [pinned official setup implementation](https://github.com/axboe/liburing/blob/d41bf9220ec39277ff235379e9089d9e0fd6c2a5/src/setup.c), not an enabled polling mode. [Exact probe records, identities and resources](../benchmarks/results/flash-io-uring-probe.json).

V2 remains a failed harness receipt: its reads completed, but its old check wrongly required returned flags 0. V3 narrowly corrected that expectation, retained raw flags and obtained a new passing run. No old failure was relabeled a pass.

This proves availability for the tested owned file/process/filesystem only. No io_uring engine backend, model timing, engine cancellation/lifetime qualification or speed gain follows. A separately reviewed minimal backend and exact byte/error/drain tests must precede a one-axis engine screen. All model runs retain original 512 experts/native top-10, exact correctness, memory/reserve/swap/lease/lifecycle and power gates. Nothing here promotes a profile or automatically starts a full task.
