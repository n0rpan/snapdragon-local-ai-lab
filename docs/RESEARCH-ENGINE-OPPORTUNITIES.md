# Snapdragon inference engine opportunities

**The best remaining opportunities are avoiding repeated Flash prefill, fixing demonstrated scheduling overhead, and overlapping narrowly identified SSD waits.** Npurun/QNN can provide a useful small helper; they do not establish an accelerator for the large models. ARM kernel alternatives deserve one controlled comparison, after checking which kernels actually execute. DS4, Sushi and oMLX contribute concrete state, I/O and verification designs, rather than transferable Apple/CUDA token rates. This source review ran no models, builds or hardware tests and establishes **no new laptop speedup**. Complete the finite short-screen queue below, select one combined configuration, then spend on final protected-agent validation.

## The measured bottleneck limits storage-only gains

Flash’s earlier 768.123-second attribution contained **422.713 seconds prefill, 328.032 seconds decode and 101.565 seconds exposed SSD wait**; the wait overlaps phase totals. Eliminating that recorded wait alone would save 13.2%, not double performance. This is an older IO4 attribution, not an IO8 ceiling or a pure-compute measurement. The matched IO4→IO8 full task improved **768.484→736.838 seconds**, with all correctness checks passing; different output lengths limit attribution. Historical 1175.218→736.838 seconds remains useful context, but cannot all be credited to our changes. ([Profile](FLASH-NEXT-PROFILE.md))

Cache research has progressed beyond the earlier report. **All 41 native regressions now pass.** HOT25 at the same 12 GiB was flat/slower: wall +0.52%, decode −0.60%; do not promote or repeat it as an untested win. Cache13 improved fixed-screen decode **2.26%**, with exact answers and recovery, but has no completed full-task comparison. Its baseline was intentionally stopped at 205.774 seconds when the user deferred long validation; that elapsed time is not a task result. ([Native gates](../benchmarks/results/flash-cache-policy-native-tests.json), [HOT25](../benchmarks/results/flash-hot-cache-screen.json), [cache13](../benchmarks/results/flash-cache13-screen.json), [deferred comparison](../benchmarks/results/flash-cache-full-deferred.json))

## Check CPU dispatch before buying another quantization track

The qualified classic engine already includes I8MM, FP16, BF16, repacking and KleidiAI 1.32.0; source commit **`954de248ac6907dd05dc19f0f511ab18f2807a54`** is tied to the recorded binary and patch. Native repack includes Q5_K/Q6_K I8MM paths for eligible shapes. KleidiAI accepts ordinary `MUL_MAT`, but not routed `MUL_MAT_ID`; compatible ordinary matrices can select KAI before native repack in this source. **Mixed Q5/Q6 weights are not automatically generic-only.** Preserve provenance and collect actual buffer/call evidence before attributing performance to build flags. ([Recorded provenance](../patches/llama-source-provenance.json), [existing model tracks](CROSS-MODEL-OPTIMIZATIONS.md))

The genuinely new cheap knob is `GGML_KLEIDIAI_CHUNK_MULTIPLIER`, default 4, which changes non-SME column scheduling too. Test it only after observing relevant KAI calls. Dense is the cleaner first target; resident MoE expert work falls outside KAI’s ordinary-matmul path. PR28673’s advertised `nrc==2 && by==0` branch has no demonstrated eligible current caller here, so skip a blind cherry-pick. A pinned **ik_llama.cpp `39fc3128ccc428314a64b98de09af24bd7bb4990`** same-GGUF CPU comparison is more credible: it supports ARM_NEON and the relevant graph families, but loader, templates, prefix formats and MTP compatibility remain gates. FastPath64’s IQ4_XS patches accelerate a different weight type and do not accelerate today’s Q4_K_M or Flash IQ3_XXS merely by installation. ([PR28673](https://github.com/ggml-org/llama.cpp/pull/28673), [ik source](https://github.com/ikawrakow/ik_llama.cpp/blob/39fc3128ccc428314a64b98de09af24bd7bb4990/README.md), [FastPath ARM implementation](https://github.com/Marc-Dvci/fastpath64/commit/5f9c3ef93b7b066a4bcec75a3a82c215b2b9beaf))

### Flash-specific current-weight KleidiAI gate

The [pinned source/descriptor audit](../benchmarks/results/flash-kleidiai-source-eligibility.json) identifies **249 Q6_K and 248 Q8_0 matrices** that could select different KAI I8MM/DOTPROD kernels on Oryon. Native repack already covers those ordinary matmuls; additional operator coverage is limited, but equal performance has not been measured. Routed expert matmuls and the protected row tables remain outside this scope. Flash currently disables extra buffer types, so enabling a build option alone establishes no dispatch.

This is a separate numerical-quality track: native Q6/Q8 packing rearranges existing blocks, while the pinned KAI path dequantizes and requantizes using one int8 scale per full row. Its source-sized row data is 565,304,320 bytes larger before padding, and its largest single packing temporary is 635,699,200 bytes. Neither is a measured peak or an admission claim. New buffer ownership, numerical and allocation checks must precede one conditional fixed screen after native repack. The original control must reproduce its baseline; a numerically different candidate needs independent correctness, repeatability and explicit output-length accounting. No KAI speedup or quality result is claimed.

## Flash prefix closure can save more than another cache policy

Classic instruction/tool-prefix persistence already produces substantial task savings. Flash’s durable equivalent is promising for **repeated starts or model switches**, not the first uncached request or an existing RAM-cache hit. Native partial checkpoints omit retained non-SWA attention KV; writing them to disk is insufficient. Full hybrid-indexed serialization does include QSA index state and recurrent PLE-convolution rows. The remaining question is complete application closure: token/hash history, positions, output/nextn dependencies, sampler and speculative-driver bookkeeping. These findings concern the recorded Flash source family, not a newly certified binary. ([Flash provenance](../dependencies/flash-source-provenance.json), [prefix status](FLASH-NEXT-PROFILE.md), [Sushi’s architecture-specific state contract](https://github.com/beamivalice/sushi/blob/904b0f6e4819b5dea627806f90d75d0b5c2ae7ba/docs/engine-prefix-cache.md#L21))

Use a synthetic public static prefix, destroy the process, restore and compare divergent continuations at identical chunk boundaries. A pre-final-token snapshot plus exact replay could regenerate outputs, but must prove all hidden/head inputs are refreshed. Bind snapshots to model, tokenizer, template/tools, build, context, dtype, positions and arithmetic schedule. Keep one user-only atomic snapshot containing static instructions only; count temporary serialization copies. oMLX’s boundary snapshot store supplies useful bounded-state design, while its lossy GDN compression does not fit this track. ([oMLX boundary store, `2165e757…`](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/cache/boundary_snapshot_store.py))

Two I/O ideas remain distinct. DS4 coalesces only adjacent source **and destination** extents with matching projections; our existing dynamic queue and projection-major ordering should remain. Exact PLE lookahead stages rows for **known next prompt tokens**, with owned history, cancellation joins and synchronous fallback. Router prediction instead guesses future expert reads: it must never replace actual routing. Its async candidate still needs stale-epoch, wrong/late/missing prediction and cancellation proof; the 41 hot-cache regressions do not qualify that separate mechanism. ([DS4 copy planner, `b3f50180…`](https://github.com/antirez/ds4/blob/b3f50180ec2c7324892be1f50bc83555ccb8d5e7/ds4_cuda.cu#L29125), [PLE failure/parity tests](https://github.com/antirez/ds4/blob/b3f50180ec2c7324892be1f50bc83555ccb8d5e7/tests/test_qwen4_ple_prefetch.c), [Sushi bounded prefetch](https://github.com/beamivalice/sushi/blob/904b0f6e4819b5dea627806f90d75d0b5c2ae7ba/docs/engine-expert-streaming.md#L215))

Flash MTP remains a conditional opportunity. The separate 2.786-GB head passes necessary structure checks, not complete payload/runtime/admission qualification. It owns a separate model/context and uses its own embeddings/output: `ctx_other` does not automatically alias target weights. Narrow draft microbatches are already implemented. Establish the full allocation ledger before depth 1→2→4 screens, including prefill catch-up, verify rows, union-of-experts reads and rollback state. Do not lower admission estimates or substitute differently quantized tensors to make it fit. ([MTP assessment](FLASH-MTP-ASSESSMENT.md), [Sushi exact row/rollback contract](https://github.com/beamivalice/sushi/blob/904b0f6e4819b5dea627806f90d75d0b5c2ae7ba/docs/engine-mtp.md#L244))

## Exhaust finite screens, then validate the selected configuration

Ranks combine likely task benefit with implementation and benchmarking cost; they are engineering judgments, **not measured gain forecasts**. Each eligible performance comparison uses the fixed code screen in ABBA order, matched settings and ≤600 seconds per arm. Stop an axis after at most two nonwinning candidates. Source, dispatch or model-free tests should reject ineligible candidates before inference. Cache13 is already a survivor; do not spend another long pair proving its 2% alone.

| Rank / change | Prerequisite and exact short screen | Cost, gain scope and stop condition |
|---|---|---|
| 1. Scheduling and KAI chunking | Finish quota/thread correction first; retain `cpu.stat`. Prove KAI placement/calls, then default 4 vs 1; try 8 only with imbalance evidence. Same dense file first, MoE second. | Low cost; prefill/total benefit unknown. Skip without KAI calls; stop on flat total time, oracle failure or desktop regression. Touch harness/environment and numeric diagnostics. |
| 2. Durable Flash static prefix | Prove full state closure; cold recompute vs export/destroy/reopen/restore, three public suffixes, corrupt-cache fallback. | Medium/high; potentially large recurring prefill savings, none promised for first cold task. Stop on continuation drift, incomplete state or serialization peak. Touch session/envelope/tests. |
| 3. Adjacent prefill coalescing | Count adjacent extents first; current vs bounded merge at fixed IO8/cache, same readiness boundaries. Synthetic EOF/cancel/partial-read tests precede model screen. | Medium; bounded by reducible read-service cost. Stop if adjacency is scarce, first-needed bytes are delayed or wall time is flat. Touch reader/job planner/tests. |
| 4. Known-token PLE lookahead | Measure PLE-specific exposed wait on the small prefill screen; synchronous vs one-chunk staging inside existing row budget. | Medium; no useful gain if PLE wait is negligible. Exact logits/frontiers and DS4-style failure parity required. Touch RowStream/prefill/tests. |
| 5. Router prefetch | Epoch ownership and wrong/late/missing/stale/cancel tests first; off/on at same cache and demand priority. | Medium/high; unknown benefit. Cap useless bytes, report byte-based waste; reject if speculative contention outweighs reduced demand stalls. Touch isolated predictor/source/tests. |
| 6. Same-GGUF ik CPU | Isolated pinned build; dense classic vs ik target-only; MoE target-only then production-equivalent MTP pool 3 only if supported. | Moderate integration; unknown gain. Stop at incompatibility or <5% repeatable screen benefit unless integration is trivial. Match cold/warm prefix state; never load classic snapshots blindly. |
| 7. Flash MTP | Payload identity and owned-allocation ledger first; serial vs depth 1, then 2/4 only with favorable acceptance/cost. | High; decode improvement can lose through prefill/cache pressure. Stop at >5% time loss, state drift or memory failure. Touch ledger/driver/rollback tests. |
| 8. Numeric and memory tracks | Confirm anonymous/file-backed pages before mmap vs no-mmap; locking separately. Q6→Q8 non-expert candidate only after converter fix; original experts unchanged. | Memory-mode test cheap; conversion costly: +0.915 GiB weights, a fresh ~84.6-GB output. Quality and total RAM/I/O tradeoffs required. Stop if benefit is consumed by cache shrink/traffic. |
| 9. NPU helper branch | CPU SDK tokenizer parity passed; qualify the cached/retiring V7 worker through all native fixtures and idle cycles before a loaded-helper latency comparison. Confirm linked QAIRT source before workers 0 vs 1, polling separately. | Cheap helper latency gain possible; no Flash decode gain implied. Exact token parity, full fixture quality and idle recovery required. Touch bridge/qualification, later dispatcher. |

The goal’s named source-coalescing/io_uring work and conditional **one bounded Vulkan dense/attention prefill test** remain tracked requirements. Source or profile evidence can close an unsupported or nonbeneficial gate; this report does not silently drop those items. Generic GPU sweeps remain out of scope. ClassLRU, fixed per-layer cache allocation, io_uring and surgical CPU fusion remain **conditional**, not an automatic second queue. Require trace/dispatch evidence that they address material remaining cost; HOT25 already demonstrates why higher hits need not help. ik’s new ClassLRU is a CUDA/offload result, not a resident-MoE or Snapdragon result. IQ4_XS/STQ/EXL3 need separate artifacts/kernels/quality budgets. Apple Metal/NAX kernels, large-model NPU mapping and more generic GPU sweeps are outside this bounded completion path. ([ClassLRU](https://github.com/ikawrakow/ik_llama.cpp/pull/2861), [Sushi format scope](https://github.com/beamivalice/sushi/blob/904b0f6e4819b5dea627806f90d75d0b5c2ae7ba/docs/engine-exl3-experts.md))

## A small NPU helper is useful after lifecycle qualification

Keep the working Linux Rust→QAIRT pipeline. Npurun **`9f6fa48522d3b1f1222b1f6d9c7fc130fb4b06e0`** uses Windows libGenie; its graph-switching fix and polling results do not transfer automatically to explicit QAIRT prefill/decode phases. Our admission bridge reparses tokenizer JSON per request, then pipeline string generation tokenizes again. First cache the worker-owned CPU tokenizer while preserving pre-load rejection and exact token counts; carrying IDs through generation is a separate parity change. The QAIRT controls `GENIEX_DECODE_WORKERS` and `GENIEX_DECODE_POLL` exist at plugin pin **`34cc633df34c69acb478305c917d5256cafb3551`**, but the linked runtime must match before testing. ([Npurun engine](https://github.com/bpbonker/npurun/blob/9f6fa48522d3b1f1222b1f6d9c7fc130fb4b06e0/crates/npurun-core/src/engine.rs), [QAIRT implementation](https://github.com/qualcomm/geniex-qairt-plugin/blob/34cc633df34c69acb478305c917d5256cafb3551/core/src/llm/llm_model.cpp))

Five titles worked at 4.706 seconds cold and roughly 0.9 seconds warm, but unloaded idle retained about 245 MiB until process exit. The retirement fix passes 19 Rust tests and two socket mocks; **native 20-fixture/four-cycle V6 remains unrun**. Finish that, portable device/config paths, permissions, dispatcher ownership and aggregate co-residency accounting before activation. Titles are not coding-quality evidence. The official 1.7B X Elite asset is a later helper option, not a prerequisite or proven Linux replacement. ([Helper status](NPU-HELPER.md), [retirement receipt](../benchmarks/results/npu-helper-idle-retirement-build.json), [Qualcomm asset](https://huggingface.co/qualcomm/Qwen3-1.7B))

Completion means supported high-value screens are accepted/rejected with receipts, the selected combined configuration passes the unchanged full task and independent oracle, and switching/prefix/idle cleanup works. Preserve 512/native top 10, Flash 21.5 GiB admission, actual 2 GiB host reserve, classic model+3 GiB/high 24/max 25, zero own swap and one heavy lease. Record thermals/throttling and battery assistance above the 20% cutoff. Publish source/model pins and failures; push nothing. The MIT wrapper does not relicense SDKs, weights or borrowed Apache/BSD components. Retain applicable notices.
