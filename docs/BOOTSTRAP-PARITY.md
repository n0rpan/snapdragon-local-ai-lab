# Bootstrap parity: required finish gate

**Status: preparation implemented; clean-install parity NOT passed.** The downloadable project must reconstruct the modified engines, selected weights, runtime/services and Local AI panel on a fresh installation, then pass new correctness and lifecycle checks. The working laptop and its historical qualification receipts cannot stand in for that test. The current manual guide is not completion of this gate.

The preparation/staging module makes no host/configuration changes, source downloads, native builds or model runs. A separate [guarded source-only executor](BOOTSTRAP-SOURCE-FETCH.md) is the first live acquisition step; its success cannot establish build, install or inference qualification.

The release acceptance target includes the modified engines and tested settings, local browser chat and image interfaces, ordinary OpenCode using local MoE, optional qualified model selection, and the always-visible right-side Local AI panel. The installed controls must load on demand, switch and unload models, and release memory. A newcomer needs linked dependencies, exact model identities and licenses, setup diagnostics and rollback. No personal Work directory, pre-existing installation or unpublished patch may be a prerequisite.

**First live acquisition check passed:** a new directory fetched only the two pinned public Flash repositories, replayed the mapping patch, and verified all 5,253 tracked source blobs/modes. It took 9.49 seconds with a 323.6 MiB cgroup peak, no new global swap-outs or memory/PID limit events, and all children reaped. The [identity-bound source receipt](../benchmarks/results/bootstrap-flash-source.json) explicitly records `compiled:false`, `qualified:false` and clean-install parity false. Source acquisition alone does not qualify a build or installation.

**Fresh Flash build and four native software checks also passed:** the isolated, network-disabled serial build completed in 574.75 seconds with a 1.26 GiB peak; config, parameter, mapping-release and file-reader executables then ran successfully with no skips. No new global swap-outs or max/OOM/PID events occurred. [Build/check receipt and both failed preflights](../benchmarks/results/bootstrap-flash-build.json). These are real compiled checks, without GGUF inference. Fresh classic/image builds, model/agent/lifecycle checks and full installation acceptance remain open.

**Selected artifact acquisition/resume passed:** the pinned 335,304,388-byte VAE downloaded and verified in 9.81 s. A separate encoder transfer was deliberately stopped after a durable checkpoint, then resumed from the same cache and verified the complete 2,497,281,120-byte artifact in 59.22 s. [Live attempts, controlled stop and evidence limits](../benchmarks/results/bootstrap-selected-downloads.json). These are clean acquisition checks for two selected assets, not proof that the remaining MoE/Q8 downloads, image pipeline or full installation passed.

The [sandbox source installer](BOOTSTRAP-INSTALL.md) now passes eleven focused tests, including rollback at all 15 tiny-fixture mutation checkpoints, existing canonical-inode/provider/layout preservation and edited-file handling. All [135 repository software tests](../benchmarks/results/repository-software-tests.json) passed in a bounded host unit. The initial restricted-tool attempt failed on denied local sockets/process controls; assertions were kept unchanged. The installer deliberately does not yet handle live-user activation, binaries/models or crash/SIGKILL acceptance. Those remain release requirements.

## Product boundary and defaults

The default install is **CPU MoE coding + Q8 CPU images**, lazy-loaded with private files and one canonical inference lease. Download only four selected artifacts: the Ornith MTP MoE, Q8 diffusion, image text encoder and compatible VAE. Their pinned byte total is 26,355,107,676 bytes (about 24.55 GiB), excluding engines/build space. Dense is an explicit additional selection. Q4 images, Arete, Flash, NPU, voice, VL and RAG must not appear as usable installed modes merely because a catalog/example mentions them: offer only modes whose assets, engine and local qualification pass. No GPU/NPU backend or new reasoning/KV policy becomes a default here.

Weights have separate licenses. QNN/QAIRT libraries, compiled vendor bundles and other proprietary dependencies remain external; the MIT project must provide acquisition links/contracts rather than redistribute them. No voice/VL/RAG implementation or quality qualification is established by this bootstrap.

## Implemented preparation CLI

New [bootstrap.py](../src/snapdragon_ai_lab/bootstrap.py) reads the existing public manifests/examples and copies only into a **new** bundle. It does not import Studio, invoke the existing host installer, start services, enable ready/validated flags, or fetch anything. The stage contains runtime/control/panel assets, unit templates, wrapper notices, private directories, one fresh staged canonical lock, inactive OpenCode fragment, asset plan and per-file/directory identity inventory. Historical binary hashes are cleared until the new build is qualified. Default runtime profiles contain the default MoE only; the dense 27B was retired in v0.1.2 and `--include-dense` now stops with that reason.

From the source checkout:

```sh
PYTHONPATH=src python3 -B -m snapdragon_ai_lab.bootstrap plan --target-home /tmp/local-ai-clean-user
PYTHONPATH=src python3 -B -m snapdragon_ai_lab.bootstrap stage /tmp/local-ai-bootstrap-stage --target-home /tmp/local-ai-clean-user
PYTHONPATH=src python3 -B -m snapdragon_ai_lab.bootstrap verify-stage /tmp/local-ai-bootstrap-stage
```

The destination must be absent and have no symlinked parent. The target HOME is a rendering input, not a directory this command installs into. Units retain systemd `%h`; do not run the staged units under the real user's manager and assume `%h` points at the test home. Panel assets are staged, not registered in a live layout. The inactive OpenCode fragment does not by itself configure OpenCode. CLI wiring into the ordinary command and wheel resource packaging remain explicit review items; this module currently requires a source checkout or `--project` pointing to one.

The injected `verified_fetch` helper has size/SHA checks, cached-file rehash, create-only publication and stop callbacks. It has **no network CLI**: production lease/power/deadline/resume integration is still required. The injected `apply_pinned_patch` helper verifies clean commit/patch identity and self-contained, unshared Git metadata before applying in an isolated tree. It never clones, compiles or changes a vendor tree automatically.

Nine focused model-free tests cover fresh selected staging, no target-home write, false qualification flags, existing-config preservation, path/symlink rejection, stage mutation detection, mocked fetch corruption/stop handling and real patch replay on a tiny generated Git repository. They do not qualify native engines or a complete installation.

## Bounded implementation sequence

1. **Finish public inputs.** Publish every required source delta, selected submodule/compiler/dependency pin and license link. Add package resources and CLI entry wiring after source review. Freeze the bootstrap input manifest and plan digest.
2. **Selected fetch and builds.** Add the guarded resumable fetch and serial build executor. One heavy job at a time, canonical lease, external power/start reserve/20% cutoff, actual 2 GiB host headroom and own zero swap; use reviewed per-step CPU/memory/task/deadline caps. No unlimited retries or broad weight downloads. No existing user service/config change at this stage.
3. **Stage and verify.** Create a fresh prefix and render new binaries/models/configuration. Bind profiles to the new binary/model SHA and exact settings. Record disabled optional modes. The current preparation module supplies this stage's file/identity foundation, not a passed install.
4. **Install transaction.** Preflight existing paths/configuration and fail safely on collisions; use versioned runtime directories and a journal. Never replace a live lock inode. Prepare any structural OpenCode merge and panel layout update for review, with backups and an automatic rollback for each failure point. Services start as lazy frontends only after their readiness criteria pass.
5. **Clean-install acceptance.** Run the checks below in a new user/systemd-user session with isolated HOME/XDG/state, no old prefix/cache/proofs and an isolated network namespace or otherwise collision-free ports. Controller ports are configurable; Studio/control/panel use fixed loopback endpoints, so a plain alternate HOME alone does not isolate the live laptop.
6. **Release only after acceptance.** Keep input/source/build/model/install/test/rollback receipts. `end_to_end_parity_passed` becomes true only from the complete acceptance result; a successful stage, build or old laptop proof cannot set it. Optional profiles get their own identity-bound receipts before appearing usable.

Require complete final response, tool execution, actual source edits, unchanged protected files, correct tests, EOF/client exit and finite complete-task time. Verify fresh prefix reuse across a full unload/reload without borrowing the original prefix store.

Keep one authoritative memory peak plus sampled RSS separate; no zero-pressure claims if events/PSI occurred.
- Exercise restart/login behavior, interrupted download resume and injected install failure/rollback. Uninstall removes only owned unmodified program/config files, preserves user files and the shared lock, and leaves the prior setup intact where one existed.
