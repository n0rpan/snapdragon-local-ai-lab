# On-demand Flash-Next planning

The installed Flash-Next profile supports larger offline planning and review on the 32 GB Snapdragon X Elite laptop. Its protected full-agent qualification passed in 1175.218 s with 12/12 independent tests and a complete final response. The complete normal-endpoint planning/image-handoff workflow also passed separately in 238.448 s. [Installed lifecycle evidence](../../benchmarks/results/flash-next-normal-lifecycle.json) [Final task evidence](../../benchmarks/results/flash-next-final-agent.json) Ordinary coding keeps the 35B MoE model as its explicit default. The portable example stays disabled and has no admission budget until measured evidence supplies one.

The Local AI panel's Flash-Next planning selection is lazy. It loads on the first request, shares the exclusive inference lease with MoE and images, and unloads after 120 seconds idle. The OpenCode action for this selection and `local-ai plan` launch the named local-plan agent with a per-process read-only permission overlay. The actual pinned OpenCode 2.2.6 probe verified directory/file reads and denied write/shell using the same no-auto launch mode. Selecting local-plan manually inside another unrestricted client does not apply that overlay. The ordinary build agent and global MoE choice are preserved.

The model has context 16384, input limit 12288 and output limit 2048, with greedy nonthinking generation. All messages and project instructions are retained; exceeding the context budget requires a smaller task rather than automatic global prompt trimming. Large cold prompts can take many minutes on CPU. Flash socket and local provider timeouts allow 1800 seconds; the classic backend retains 900 seconds.

The qualified configuration preserves all 512 experts and native top 10 routing. It uses 12 GiB expert cache, CPU 4 decode/6 batch, OpenMP 6 passive/non-dynamic, IO 4, overlap, microbatch 4096 and disabled THP/repack. Dense weights use anonymous RAM; the ngram tensor stays demand mapped; missing experts use raw-offset O_DIRECT SSD reads. The demand-mapping patch reduces startup I/O and memory pressure without changing tensor offsets or numerical operations. Its measured startup gain and limits are documented in [FLASH-NEXT-SPLIT.md](FLASH-NEXT-SPLIT.md). It provides no established decoding improvement by itself.

Admission counts the greater of measured RSS and final cgroup peak, without subtracting file-backed pages, alongside a conservative cache/working-set estimate. Start requires the admitted budget plus 4 GiB available RAM. A one-second monitor stops/reaps the Flash child if live available RAM drops below 4 GiB or battery reaches 20%; start requires at least 30% battery. Battery use is allowed; external power remains mandatory for qualification benchmarks. The unchanged parent chat unit has 24 GiB memory.high, 25 GiB memory.max, zero swap and Tasks 256. These limits and the watcher do not constitute a hard 4 GiB reservation.

Native HOME and all XDG directories are private 0700 directories under backend data. Native environment and OpenMP settings are fixed, with no real user auth/history paths inherited. Flash prompt/context reuse remains in RAM and disappears on unload; Flash disk prefix persistence is disabled. The existing classic prefix cache is preserved. The proxy does not log prompts or native output. OpenCode's own client session storage follows its ordinary behavior; this setup does not claim to disable that client feature.

The laptop deployment installed an immutable runtime bundle and server artifact after exact source/binary/model and full-agent proof checks, retaining backups of changed configuration, controls and units. Normal verification has passed navigation, Flash readiness, real idle unload/RAM recovery and MoE/Flash switching. The earlier Image Studio handoff failed; after installing the narrowly scoped 1-to-15-second unload-timeout fix, the complete rerun passed actual Q8 generation, PNG checks, chat exclusion and final unloaded/idle/RAM recovery. Restore the previous immutable unit paths and backed-up files to roll back. No normal llama or image runtime is replaced.

For manual configuration, merge the [OpenCode planning fragment](../../examples/flash-next-opencode.fragment.json) while preserving the explicit ordinary MoE model. The fragment alone does not qualify or load Flash and does not apply the launcher's read-only policies. Use `local-ai plan` for that supported launch flow.
