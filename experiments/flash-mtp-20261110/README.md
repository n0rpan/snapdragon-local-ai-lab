# Flash MTP acceptance screen

`run.py` runs one opt-in acceptance arm using BigMoe's merged NextN head and exact verification (private engine PR #2). It uses the existing fixed353 code-screen protocol and independent Python oracle. The caller must supply the canonical inference lease, a swap-disabled bounded scope, the existing MemoryGuard and power checks; the script itself does not acquire a second lease.

The fixed353 workload retains its original prompt and independent code oracle. Bit identity remains a diagnostic. After the owner's numeric-gate amendment, a changed answer may pass only with `--batch-noise-proof`: a recorded finite verify-versus-single KLD no larger than measured production batch-versus-single noise on the same original model shards and positions 100–350. The receipt is copied by hash into the arm report; absent proof leaves the original identity gate in force. A second synthetic LRU-code prompt measures acceptance on non-repetitive code, capped at 512 tokens; truncation is reported and is not a completed-code quality pass. For both prompts compare MTP off with depths 1, 2 and 3, using the same target and Q4_K_M merged head. `--mtp-p-min 0` avoids abstention confounding the depth comparison.

The small local instrumentation adds per-turn proposed and accepted counts by draft position to `RunSummary` and `BMOE_DONE`. Counters include an accepted EOS draft, match the existing aggregate totals, and do not store draft text/IDs. All counters are observational; no model arithmetic or sampling changes. This permits reporting both total acceptance and prefix survival at each depth, rather than inferring them from a combined percentage.

Report request time, prefill time, effective decode time including drafting/catch-up, output hash/count, counts by position, memory peak, available-RAM minimum, guard state and swap/OOM events. The native headline tok/s excludes some speculation overhead and must not be substituted for effective throughput. This is acceptance research for the Rust engine; nothing is deployed and it does not establish a full-agent speedup.
